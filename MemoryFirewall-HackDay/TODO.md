# MemoryFirewall delivery checklist

- **Full-stack runtime and route manifest:** The application server listens on the configured port, binds to `0.0.0.0`, serves the React client, exposes `GET /manus-routes.json`, and supports `/`, `/overview`, `/memories`, `/replay`, `/tests`, `/settings`, and `/how-it-works`.
- **Cosmic developer console shell:** Opening `/` shows the MEMORYFIREWALL shield mark, Refund Support Agent project, DEMO / SYNTHETIC DATA badge, Gemma 4 / fallback ready indicator, API ONLINE status, navigation, memory health, responsive mobile layout, and glassmorphism cosmic styling.
- **Working backend API and seeded data:** `GET /api/health` returns HTTP 200 with `{ ok: true }`; dashboard metrics load seeded values; list/filter memory, passport, runs, tests, explanations, test generation/run, and memory action endpoints return real in-memory records and useful errors.
- **Reliable baseline/protected demo:** Run unsafe baseline calls the backend and shows an unsafe ₹18,500 refund; Run with MemoryFirewall calls the backend and shows a blocked-safe result with `mem_1042` influential; Reset demo restores initial state; Run demo executes the protected flow and opens the result.
- **Decision replay and human approval:** Protected runs record request, retrieved memory, validation, agent decision, tool call, block/allow result, and outcome; replay shows the timeline and explanation; an approval request can be reviewed, approved, rejected, and audited without executing a real refund.
- **Memory ledger and passport actions:** The ledger supports search and status filters, row selection opens a passport with source, trust, confidence, impact, scope, evidence, expiry, and decision usage, and verify/quarantine/revoke/set expiry actions update backend state with feedback.
- **Regression test workflow:** Generate memory test creates `unverified_refund_approval_must_not_trigger_refund`; run tests returns PASS with expected and actual `request_verification`; replay-after-fix is visible; export YAML downloads a real file.
- **Auth flow:** Sign up and sign in forms call backend endpoints, show pending/error/success feedback, persist a demo session token, and allow sign out. Auth is clearly labeled synthetic demo auth and does not claim production security.
- **How it works education:** The app includes a step-by-step developer integration guide explaining write validation, protected retrieval, deterministic enforcement, human approval, replay, and CI regression tests.
- **Embedded onboarding video:** The How it works page embeds a playable video generated from the product’s visual system, explaining how a new developer integrates and uses MemoryFirewall.
- **README and honest limitations:** README includes overview, problem, architecture, feature list, setup, API overview, demo instructions, Gemma role, synthetic-data disclaimer, security/privacy limitations, license, and roadmap.
